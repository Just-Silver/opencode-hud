# 额度刷新倒计时 + HUD 秒级心跳

- 日期：2026-11-15
- 状态：**已实现**
- 落点：`model/quota.ts`（`nextCheckAt` / `quotaStatusTrail` / `nextWakeAt`）、`model/types.ts`（`QuotaStatus`）、`shared/format.ts`（`fmtCountdown`）、`view/hooks/useQuota.ts`（调度）、`view/hooks/useClock.ts`（共享心跳）、`view/QuotaSection.tsx`

## 1. 目标

额度组头右端原来是「距上次成功刷新的数据年龄」（如 `3m`）。它只能证明「数据存在」，看不出 HUD 是否还活着，也说不出什么时候会更新。改为**下次刷新倒计时**后：

```text
▾ OpenAI                 ↻ 04:32
```

数字每秒变化，HUD 有没有在跑一眼可见；同时它必须与真实调度一致，不能是装饰。

**与「额度窗口重置提示」的区别（不要混）**：本倒计时是本插件**下一次去查额度**的时刻；`↻ 4h12m` 是供应商额度**窗口重置**的时刻，由 provider 写进 `QuotaItem.hint`，两者数据来源、刷新节奏、失效方式都不同，刻度也不同（秒级 vs 小时/天级）。额度窗口重置提示不变。

## 2. 状态语义（优先级即实现顺序）

`quotaStatusTrail(status, open, now)` 纯函数，`now` 来自共享秒级时钟：

| 优先级 | 条件 | 展开态 | 折叠态 |
| --- | --- | --- | --- |
| 1 | 请求在途 `fetching` | `↻ 更新中`（琥珀） | 不占位（摘要优先） |
| 2 | 有错误，且能算出下次允许请求时刻 | `重试 09:28` / `凭据失效 09:28` / `限流 09:28`（红） | `失败`（红） |
| 3 | 有错误，但算不出时刻 | `凭据失效 8m`（红，原因 + 缓存年龄） | `失败` |
| 4 | 缓存过期（无错误） | `旧 12m`（琥珀） | `旧`（琥珀） |
| 5 | 正常等待 | `↻ 04:32`（灰） | 不占位（摘要优先） |
| 6 | 算不出时刻、只有数据年龄 | `3m`（灰，兜底不伪造倒计时） | 不占位 |
| 7 | 无数据无错误 | 不渲染 | 不渲染 |

规则细节：

- **具体原因不被倒计时挤掉**：`login_expired / rate_limited / timeout / network / bad_response` 原样作为前缀；只有通用 `provider_error`（「查询失败」）换成「重试」，因为后者没有额外信息。
- **`Retry-After` 优先于本地退避**：`nextCheckAt` 先取 `retryAt`，没有才用 `at + backoff(failures)`。
- **年龄/过期的唯一公式是 `quotaAge(updatedAt, now)`**：`status()` 的快照与逐秒展示都调它，不写第二份；过期优先于倒计时，因为超过 `QUOTA_STALE_MS` 说明刷新链路已经不正常，此时说「马上刷新」是假话。
- **折叠行不给倒计时**：正常后台刷新是常态，为它挤掉额度摘要与窗口重置时间不划算；异常仍要占位（`失败` / `旧`）。
- **无有效数据的供应商继续隐藏**（`items` 为空或无缓存不出行），所以「首次加载」不会出现虚假的 `05:00`。
- **凭据切换**：store 按凭据指纹分桶，换号即丢旧桶（含 `at` / `failures` / `retryAt`），行随之消失到新账号首次成功，不会残留旧账号的倒计时。

## 3. 格式化

`fmtCountdown(ms)`：

- `<1h` → `MM:SS`（`04:32`）；`≥1h` → `HH:MM:SS`（`01:00:00`）。两种形态各自定宽，右对齐由组头弹性间隔保证，数字变化不抖。
- **向上取整**：只有剩余 ≤0 才出现 `00:00`，不会提前一整秒归零；负值 clamp 到 `00:00`。
- 非有限值 → `undefined`（调用方退回数据年龄）。

## 4. 调度：倒计时必须与真实刷新一致

旧实现是「每 60s 调一次 `load()`，由 store 判断是否发请求」。这样倒计时只能写成 `at + 5min`，而归零后最多还要等 59s 才真的刷新 —— 倒计时和调度是两套事实。现在改成两路协作：

1. **精确唤醒（主）**：`QuotaStore.nextCheckAt(pid)` 是唯一真源，返回下一次允许请求的**绝对时刻**：

   ```
   未注册端点 / 没凭据 / 从未尝试 / 有请求在途 → undefined
   retryAt 存在                                  → retryAt（服务端优先）
   其余                                          → at + (failures ? backoff(failures) : 5min)
   ```

   `useQuota` 用 `nextWakeAt()` 取所有目标里最早的一个，`setTimeout` 排到那一刻；到点 `kick()` → `load()` → store 判定条件已满足 → 真请求。倒计时文本用的也是同一个 `nextCheckAt`（经 `status().nextRefreshAt`），因此**两个数字不可能不一致**。
2. **兜底心跳（辅）**：保留 `QUOTA_TICK_MS = 60s` 的 interval，只做「凭据探测（5min TTL）+ 补一次 load」。它负责发现新登录 / 切号，并兜住漏排程；真正是否发请求仍由 store 的间隔/退避决定，所以不会增加网络请求。

不变量：

- **通知成对出现**：请求真正开始时（`inFlight` 写入之后）通知一次，落定后（成功 / 失败 / 空响应）在 `inFlight` 清空之后通知一次。只在落定时通知 → 「更新中」永远看不到，倒计时归零后界面会停在 `00:00` 直到请求结束；只在开始时通知 → 界面会钉在「有数据 + 更新中」。被间隔/退避跳过、命中并发等待的 `load` **不通知**（没有真实请求就没有状态变化）。
- 每次落定通知里 `useQuota` **重排下一次唤醒**，因此失败退避、`Retry-After`、凭据切换都不会沿用旧截止时刻；开始通知里 `nextCheckAt` 为 `undefined`（在途），只会清掉已过期的唤醒，不会排新程。
- 条件不满足被跳过时，下一次唤醒时刻由 `nextCheckAt` **重算**（不是固定重试间隔），不会产生重复请求。
- 已到点的目标被再次叫醒时最小延迟 `MIN_WAKE_MS = 250ms`，防止「时刻没前进」造成空转。
- `nextCheckAt` 在请求在途时返回 `undefined`：落定后会重新排程，此刻给时刻只会制造一次多余的 wake。
- 组件销毁（`onCleanup`）清 `setTimeout` + `setInterval`；`kick` 在 `disposed` 后直接返回，避免卸载后的迟到 promise 再排一次程。
- **网络频率不变**：最小 5min、失败退避 5→10→15min（封顶）、`Retry-After` 优先。倒计时只改变「什么时候检查」，不改变「允许多久请求一次」。

## 5. UI 心跳

`view/hooks/useClock.ts` 提供一个**模块级共享秒级时钟**：

- 一条 `setInterval(1000)`，引用计数管理：首个消费者启动，最后一个 `onCleanup` 时停止（宿主按会话重建侧边栏，不释放会留下多个计时器）。
- 信号值是 `Date.now()` 的**绝对时刻**，不是自增计数：定时器延迟、系统休眠、校时之后都直接对齐真实时间，不累计漂移。
- 心跳只喂「组头右端」这一个文本节点：`rows()` memo **不读时钟**，`QuotaStatus` 里给的是绝对时刻（`updatedAt` / `nextRefreshAt`），所以每秒更新不会重建 `QuotaRow[]`、不重跑供应商 renderer、不重算额度数据。
- `QuotaGroup` 把状态注记拆成两个字符串 memo（文本 / 颜色）：文本每秒变，颜色很少变，颜色属性不会被秒级心跳反复重设；折叠行摘要用 memo 吃字符串比较，倒计时变化不会带动摘要重绘。
- 心跳不触发任何网络请求。

## 6. 测试

`node --test tests/*.test.ts`（209 例全绿）：

- `fmtCountdown`：MM:SS / HH:MM:SS 边界、向上取整、`00:00` 只出现在真到点、非法值。
- `quotaStatusTrail`：正常倒计时、逐秒递减、定时器延迟 3.7s 后直接对齐真实剩余、跨过截止时刻 `00:00`、时间倒退回涨、≥1h 形态、在途优先、失败转 `重试/凭据失效/限流 + 倒计时`、失败无时刻退回原因 + 年龄、过期优先于倒计时、折叠行不给倒计时、算不出时刻退回年龄、无数据不硬凑文案。
- `nextWakeAt`：多供应商取最早、全无 → undefined。
- `QuotaStore.nextCheckAt`：未注册/未尝试/没凭据/在途 → undefined；成功后 = `at + 5min`；倒计时归零后 `load` 真发请求；失败退避 5/10/15；`Retry-After` 优先；切号不继承旧退避；休眠 30min 后只补一次请求并重新对齐。
- 订阅通知时机：一次真实请求**开始 `fetching=true` + 落定 `fetching=false`** 两次通知；失败/空响应同样是两次且结束时 `fetching=false`；被间隔跳过、`missing key`、命中并发等待的 `load` 不通知；并发去重仍只发一次请求。
- `layout`：`箭头 2 + 名称 14 + 1 间隔 + 注记` 在最坏注记（`凭据失效 09:28`）下仍在 33 列内。
