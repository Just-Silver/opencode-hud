# HUD 5.0：OpenCode Native Pro 重型仪表盘

- 日期：2026-11-11（初版 Obsidian Amber → 同日按实机截图改版为 OpenCode Native Pro）
- 状态：**已实现**
- 落点：`sidebar.content`（`view/Sidebar.tsx`）+ `prompt.footer.status`（`view/PerfFooter.tsx`）
- 前提：opencode2 v2.2.x、宿主侧栏固定 42 列、不改宿主、不引入新依赖、不提高网络请求频率

## 1. 目标与边界

把侧栏做成与 OpenCode 本体融为一体的开发者监控面板：

- 视觉：中性黑灰画布 + 一圈圆角卡片边框 + 琥珀强调 + 少量功能性色彩。
- 信息：上下文 / 额度 / 子代理三块的核心指标一眼可读，且不牺牲数据真实性。
- 行为：刷新不闪、切会话不残留、异步结果不覆盖新数据、折叠与展开互不干扰。

**HUD 是独立监控插件**：宿主已经显示的 上下文 / Token / MCP 不作为删除或弱化 HUD 指标的理由。所有既有指标（上下文、累计、输入/输出/缓存读写/推理/命中率、额度、子代理性能）都必须在 HUD 内可见。

非目标：新供应商、新统计公式、宿主 UI 改造、跨终端主题适配、发布流程改动。

## 2. 审计结论（先于改动）

| 类别 | 问题 | 处理 |
| --- | --- | --- |
| 必须修复 | 上一版大面积蓝灰画布（#0E1219/#1C2330）与宿主纯黑界面割裂，卡片像贴上去的面板 | 换成中性黑灰（#191919/#242424），整块 HUD 用与卡片一致的连续表面，不露更暗的间隙 |
| 必须修复 | 累计 token 画了一条 100% 满格进度条，没有上限语义 | 改为 总量 / 缓存命中 数值块；不再给累计量画进度条 |
| 必须修复 | 所有百分比一律绿色，绿色面积过大且不区分语义 | 上下文主指标用琥珀、接近上限转红；额度「已用占比」低=次级灰、中=警告、高=危险 |
| 有明显收益 | 侧栏对 34/37 列的理解混乱：外框+内边距吃掉 4 列 | 改为「一圈边框 + 左右内边距」= 内容 33 列，`view/layout.ts` 单一真源 |
| 有明显收益 | 卡片层级靠背景块堆叠，缺少真正的「卡片」形态 | 使用 OpenTUI 原生 box 圆角边框 + 边框内标题（`title`），一卡一边框 |
| 有明显收益 | 子代理运行中与已停止只有一行差别，扫视时不够醒目 | 运行中改为两行任务卡（抬升底色 + 琥珀左线），已停止保持紧凑单行 |
| 有明显收益 | 额度展开区与折叠行视觉上完全同级 | 展开区加一条左侧竖线 + 内缩，形成克制的层级 |
| 可选（未做） | 整卡折叠 | 卡片折叠后只剩空边框，视觉更差；区块内折叠（额度分组、子代理详情/历史）保留 |
| 不值得改 | 累计 token 取 `SessionInfo.tokens`、缓存率口径、耗时高水位、5min 刷新 + 5→10→15 退避、`<Index>` 行复用、spinner/耗时双心跳 | 全部保留原实现 |

## 3. 方案对比

- **A. 只换配色**：能消除蓝灰割裂，但排版仍是背景块堆叠，指标层级没有改善。否决。
- **B. 原生圆角卡片（采用）**：一卡一边框、标题写在顶边，内容 33 列；用留白、局部竖线、数值块建立层级，不叠第二层边框。
- **C. 卡片 + 内层面板边框**：视觉更「重」，但 37 列下每层再吃 2 列，正文会掉到 29 列，进度条与标题列都不可读。否决。

B 的代价是标题占掉顶边的一段（不影响列宽），换来与宿主一致的边框语言和清晰的分块。

## 4. 视觉系统（OpenCode Native Pro）

调色板（`view/theme.ts`，固定暗色，不跟随宿主主题）：

| 角色 | 值 | 用途 |
| --- | --- | --- |
| Card | `#191919` | 卡片底 |
| Raised | `#242424` | 指标块 / 运行中任务 / 更新横幅 |
| Track | `#363636` | 进度条轨道 |
| Border | `#303030` | 卡片边框、展开区竖线 |
| Accent | `#FAB283` | 卡片标题、上下文主指标、当前供应商 |
| Text | `#EEEEEE` | 主文本 / 数值 |
| Secondary | `#A9A9A9` | 次级文本、非当前供应商、已停止任务 |
| Muted | `#858585` | 标签 / 单位 / 弱化注记 |
| 输入 | `#76A9E0` | token 输入分量 |
| 输出 | `#B99AF7` | token 输出分量 |
| Cache | `#65BFA6` | token 缓存分量 |
| Success | `#86C89A` | 正常运行 / 成功结局 |
| Warning | `#E5A05A` | 中风险 / 中断 |
| Danger | `#E06C75` | 真实错误 / 高风险 |

颜色纪律：

- 琥珀是唯一强调色：卡片标题、上下文主指标、当前供应商、footer 速度。
- 绿色只表达「正在正常运行 / 成功」，不铺给普通百分比。
- 红色只表达真实错误与 ≥85% 高风险。
- 蓝/紫/青只用于 token 分量，不做装饰。

几何：宿主 42 列 − 宿主 padding 4 − scrollbox 预留 1 = **37 列**；卡片一圈圆角边框（2 列）+ 左右内边距（2 列）→ **内容 33 列**。全部常量集中在 `view/layout.ts`，不用 `onSizeChange` 实测（首帧为 0 会闪）。

### 5.1 上下文卡片

- 第一层：上下文百分比（琥珀；≥85% 转红）+ 当前/上限 + 全宽主进度条。
- 第二层：累计关键值用两个抬升底色的数值块——`总量` 与 `缓存命中`。累计量没有上限，不再画满格进度条。
- 第三层：token 明细行（真实数值 + 占总量比例）。五个分量是宿主聚合列里的**互斥统计**（`输入` 为非缓存输入、`输出` 为可见输出、`推理` 独立、缓存读写独立），但缓存读取通常占 95%+，堆叠构成条在 33 列下只会是一条满格绿，信息量为零，因此不画；占比只以文字保留。
- 保留全部指标：输入 / 输出 / 缓存读 / 缓存写（>0 时）/ 推理 / 缓存命中。
- 口径不变，见 `docs/token-accounting.md`。

### 5.2 额度卡片

- 分组与排序沿用《多订阅额度》设计（当前会话 → 运行中子代理在用 → 其余；只展开当前会话那组）。
- 组头：当前供应商琥珀加粗；其余次级灰。展开时右端是新鲜度（`更新中` / 数据年龄 / 失败原因 + 缓存年龄），折叠时右端是最紧张一条的摘要。
- 展开区：左侧一条 `Border` 色竖线 + 内缩，条目用共享渲染器（标签列定宽，进度条左缘对齐）。
- 颜色语义：百分比是「已用占比」——低=次级灰、≥50%=警告橙、≥85%=危险红；**没有缓存就不出行、失败不画 0%**，有缓存时失败仍展示缓存并标注年龄。
- 数据新鲜度来自 `额度Store.status`（`phase/fetching/ageMs/stale/error`），不把缓存数据伪装成实时数据。

### 5.3 子代理卡片

- 卡片头：`● N 运行中`（绿）`N 已停止`（次级）`N 失败`（红）——三个数各自独立，失败不藏进「已停止」。
- 运行中：两行任务卡（抬升底色 + 琥珀左侧线 + spinner + 加粗标题；第二行 `耗时 · 消耗 tok`），点击展开详情。
- 已停止：单行紧凑列表，结局点按 `SessionInfo.outcome` 上色（成功绿 / 失败红 / 中断琥珀 / 未知灰）。
- 展开详情：完整标题、状态、模型（含 variant）、代理、命中率、性能；空值行不渲染。
- 历史折叠：常驻最近 5 条已完成，其余进「还有 N 条已完成」；运行中不设上限。
- 表尾：`收起`（有展开项时可点）+ `总量` 合计（始终显示）。

### 5.4 Footer / 更新提示

- Footer：首字弱化 + 速度琥珀，计算规则未改。
- 更新横幅：抬升底色单行条 + 琥珀 `▍更新`，下载/安装/重启流程未改。

## 6. 数据层与更新机制

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| `SessionInfo.outcome` 进入 `SubagentInfo` | `model/types.ts`、`model/subagent.ts` | 宿主在 execution 终态写 `idle_outcome`，只在 `运行中=false` 时采信 |
| `额度Status` + `updatedAt` | `model/types.ts`、`model/额度.ts` | 展示元信息；`updatedAt` 只在成功写入时更新，失败不清空缓存年龄 |
| `额度StatusTrail` / `额度ErrorLabel` | `model/额度.ts` | 纯函数：在途 / 失败原因+年龄 / 过期 / 折叠前缀 |
| `subagentCounts` | `model/subagent.ts` | 运行中 / 已停止 / 失败三计数，失败不被合并 |
| `fmtAge` | `shared/format.ts` | 新鲜度短格式（刚刚 / 3m / 2.4h / 3d） |
| ViewModel 拆分 | `view/hooks/useSessionStats.ts`、`use子代理.ts`、`use额度.ts`、`useUpdate.ts` | 信号/副作用仍在渲染期创建（owner 正确），组件只做编排 |
| 额度加载去抖 | `view/hooks/use额度.ts` | 目标集合按 `join` 键比较后再加载；60s 心跳负责探测 + 限流刷新 + 刷新年龄 |
| 子代理供应商推导 | `view/hooks/use子代理.ts` | 从已组装的行推导并按内容比较，避免 1s 心跳连带重算额度 |
| 更新检查去重 | `view/hooks/useUpdate.ts` | 进程内共享同一个 `checkForUpdate` Promise |

竞态与生命周期：额度按凭据指纹分桶（切号即作废旧数据）与并发去重仍在 store；子代理展开态不跨会话复用；定时器全部 `onCleanup`。

## 7. 测试

自动化（`node --test tests/*.test.ts`，189 例全绿）：

- `额度Store.status`：未请求 / 在途 / 新鲜 / 过期 / 失败保留缓存 / 从未成功 / 错误归因；读状态不发请求。
- `额度StatusTrail` / `额度ErrorLabel`：展开与折叠、刷新中优先、失败带缓存年龄、无数据不硬凑文案。
- 子代理：`outcome` → 状态映射、`subagentCounts` 三计数、供应商推导、排序/裁剪/耗时高水位。
- `tokenMix`：分段合并、零分量、总和守恒；`fmtAge` 边界。

## 8. 视觉验收清单（重启后执行）

1. 卡片之间的空行是否与卡片同色（无更暗的断层），整块与宿主黑底自然衔接。
2. 卡片圆角边框与边框内标题是否正常渲染（`title` / `borderStyle="rounded"`）。
3. 上下文主指标是否琥珀、进度条与百分比是否对齐。
4. 总量 / 缓存命中 数值块是否等高、数值不换行。
5. 累计量是否只用数值块表达（不画无上限意义的进度条）。
6. 额度组头/展开区竖线/进度条左缘是否对齐，`0%` 只显示轨道。
7. 运行中子代理是否两行卡片、已停止是否单行、结局点颜色是否正确。
8. 长标题截断、历史折叠行、表尾 总量 是否不换行。
9. Footer 与更新横幅在窄宽度下是否仍不换行。

## 9. 未做（P2）

- Rich/Compact 双模式：33 列下两套布局的维护成本高于收益。
- 历史趋势图：没有可靠的历史上下文采样源，不为画图而持久化采样。
- 任务进度百分比：宿主不提供，不编造。
- 整卡折叠：卡片折叠后只剩空边框，视觉更差（区块内折叠保留）。
