- 落点：`sidebar.content` 内、`额度` 区块之后，与现有 `会话`/`额度` 共用同一个带边框盒子

## 1. 数据来源

全部来自宿主 `Context.data`，**不读子会话消息、不触发额外同步**：

| 展示项 | 取法 | 备注 |
| --- | --- | --- |
| 子会话列表 | `context.data.session.family(sessionID)` 去掉自身 | 宿主进入会话时已 `sync(sid, {children: true})` 填充（`CHILD_PAGE = 200` 分页拉全）；子会话结束后**不会**从 family 表移除 |
| 子会话标题 | `session.get(id)?.title` | 主行首列展示；缺失时回退 agent 类型 |
| agent 类型 | `session.get(id)?.agent` | `general` / `explore` / `build`…；在展开行展示 |
| 耗时 | 见 §2 | |
| 总消耗 | `tokens.input + output + reasoning + cache.read + cache.write` | 会话级累计聚合（`session_v2` 的 `tokens_*` 列），**含缓存读，不排除** |
| 模型 | `session.get(id)?.model?.id` | `ModelRef` 的 `id` |
| 思考强度 | `session.get(id)?.model?.variant` | 可选；缺失则整段不渲染 |
| 缓存命中率 | `tokens.cache.read / (input + cache.write + cache.read)` | 与会话区块同一口径（`model/usage.ts` 的 `cacheRateOf`）；无数据则整行不渲染 |
| 状态 | `session.status(id)`：`"running"` / `"idle"` | 用于行首状态点与耗时口径分支 |
| 结束时刻 | `time.idle ?? time.updated ?? time.created` | **只用于排序**，不展示；运行中不取（见 §3.1） |

不使用 `session.cost`（金额不展示）、不使用 `outcome`、不展示 Session ID。

## 2. 耗时口径

```
running：now − time.created
否则   ：(time.idle ?? time.updated) − time.created
```

- `time.idle` 在 `session.execution.succeeded/failed/interrupted` 时写入，语义是「最后一次跑完变空闲的时刻」。
- **运行中时 `idle` 仍是上一轮的旧值、不会清空**，因此必须按 `status()` 分支，不能无条件取 `idle`。
- 不用 `time.updated` 作为结束时刻：它会被 `viewed` / 改名 / 归档等副作用推后（实测主会话 `updated` 比 `idle` 晚 3 分钟）。
- 已知偏差：若子会话被中断后又恢复，`idle − created` 会包含中间空闲期。子代理极少恢复，接受。
- 运行中的条目需要刷新：**仅当存在 running 子会话时**开 1s ticker，全部 idle 立即停（对齐「仅 busy 时心跳」原则）。

### 2.1 排序与常驻裁剪

```
排序：running 在前（组内耗时倒序）→ 已完成按结束时刻倒序 → id 兜底
常驻：全部 running + 最近 VISIBLE_DONE_ROWS（= 5）条已完成；其余折叠成一行
```

- **已完成按结束时刻排序，不按耗时**：耗时倒序会把 `58m` 的老任务压在刚跑完的 `2m` 之上，与「最近 5 条」的筛选口径自相矛盾。结束时刻取 `time.idle ?? time.updated ?? time.created`（`idle` 语义见 §2）。
- **运行中条目不设上限**：`family()` 里的子会话结束后不会移除，列表只增不减；但任意一条重新进入 `running`（复用老子代理）时，凭状态自动回到常驻区，与它多老无关。再次结束后 `idle` 被刷新，于是成为「最近完成」的头部——**复用不需要额外机制**。
- `VISIBLE_DONE_ROWS = 5` 的依据：一次并发通常 3~5 条，5 能让「上一批刚结束 + 这一批在跑」同屏；再大就会把上方的用量/额度区块挤出视野。
- 条数守恒：`head + tail` 的顺序拼接等于原序列，折叠段只是截断，不重排。
- **耗时列不解释排序位置**：耗时是时长（`elapsedMs`），排序键是结束时刻，两者不成比例。看到 `22m38s` 排在 `1h57m` 之上是**正确行为**——该条目被复用后又结束，`idle` 被刷新成最近时刻；短任务靠前同理。不要为此把排序改回耗时倒序（那会让「最近 5 条」的筛选与展示自相矛盾）。

## 3. 布局

侧边栏可用内宽固定 **34 列**常量（宿主 42 − 宿主 padding 4 − 边框 2 − 内边距 2）。宿主的侧边栏宽度是硬编码的，所以这里不实测（`onSizeChange` 首帧为 0 会使标题在两种截断间闪）。

### 默认（每条 1 行）

``` 
▼ 子代理 ● 19  ● 0      收起  390.8M
────────────────────────────────
▶ ● Implement Task … 2h57m 100.5M
▶ ● Final cleanup f… 1h57m  19.6M
▶ ● Final whole-br… 1h28m  45.6M
▶ ● Final fix wave… 1h23m  47.1M
▶ ● Implement Task … 1h20m  33.7M
▶ 还有 14 条已完成
```

- **常驻 5 条已完成 + 折叠行**（口径见 §2.1）：子代理多时只留最近 5 条，其余塞进 `还有 N 条已完成`。行首箭头 `▶` 表示当前已折叠，点一下变 `▼` 并逐条展开，再点收回。
- 折叠行用 `MUTED_COLOR`，与「收起」同色的弱化灰；合计消耗不在这行重复（标题行右侧已是全量）。
- 「收起」按钮同时清掉逐条展开与折叠行展开态（只收一半读起来像没收干净）。
- **标题行状态指示灯**（紧跟标题，展开/折叠都显示）：`● 19  ● 0`，**黄=已停止、绿=运行中（已停止在前）**。圆点与数字之间留一个空格（贴死会被读成形状而非计数），两个指示灯之间留两个空格；数量为 0 也显示，否则「全停了」与「全在跑」在视觉上无法区分。与上游 `●35 ●1` 形态一致，但语义写死为「已停止 / 运行中」，不再有上游那种「●N 是已完成、另一个 ●N 是失败」的歧义。
- **标题行右端**：合计消耗（`390.8M`），展开与折叠都显示。

列预算（总宽自适应，首帧兜底 34 列）：

```
展开箭头 1 + 空格 1 + 状态点 1 + 空格 1 + 标题(自适应) + 垫片 + 耗时 6 + 空格 1 + 总消耗 6
```

- **主行是会话标题**（`SessionInfo.title`，子代理的标题即任务描述）；标题缺失时回退 agent 类型，不留空。
- 两个数值列**固定宽度** `padStart`，右缘严格对齐：耗时 6 列（`58m05s` 最长）、总消耗 6 列（`350.5k` / `999.9k` 最长）。按 5 列对齐会让 `58m05s` 溢出、各行右缘参差。
- 标题列宽度 = 行宽 34 − 行首 4 − 右侧 13 − 间隔 1；行宽是常量（宿主侧边栏宽度硬编码），不实测。
- 状态点用颜色区分、不占额外字宽：
  - **运行中** = 盲文点阵 spinner `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`，80ms 一帧（与宿主 `component/spinner-frames.ts` 的 `SPINNER_FRAMES` 同源），绿色 `INPUT_COLOR`
  - **已停止** = 静态 `●`，黄色 `WARN_COLOR`（完成与中断共用黄色，避免无谓歧义）
- **为什么不用宿主输入框的扫描条**：宿主运行态是 8 列 Knight Rider（`■⬝`，40ms），在 34 列侧边栏里会挤掉标题列；点阵只占 1 列，语义相同。
- **动画帧信号独立于耗时刷新**：帧 80ms、耗时 1s 两条心跳；帧号只传给行首 `<text>`，不参与 `subagentRows` 重算（否则每 80ms 重建全部行对象）
- 耗时格式（`short`）：`42s` / `1m10s` / `58m05s` / `1h02m`
- 总消耗复用 `shared/format.ts` 的 `fmtTokens`（`12.3k` / `350.5k` / `13.1M`）

### 展开（仅当前展开的那一条 +4 行）

```
▼ ● 最终审查三库拆分 58m05s  13.1M
    标题 最终审查三库拆分（完整，不截断，超宽自动换行）
    模型 deepseek-v4.1-flash (high)
    代理 general
    命中 98.4%
```

- **完整标题行**：主行标题必须截断才能给右侧耗时/数值列让位，展开时补一行不截断的标题，用 `wrapMode="char"` 按字符断行（中文标题没有空格，`word` 模式不会断）。`title` 缺失时不渲染该行。

列预算（三行同缩进，右缘齐）：

```
缩进 2 + 标签「模型」/「代理」/「命中」4 + 空格 1 + 值自适应（= 行宽 34 − 7）
模型值 = 模型 id + 可选 " (variant)"
```

- 主行已被标题占用，**agent 类型放展开行补全**（规格五项：agent / 耗时 / tokens / 模型 / 强度，全部齐备）
- **完整标题行**用 `wrapMode="char"` 按字符断行；不用 `word`，中文标题没有空格分隔，`word` 模式不会断行
- **思考强度跟随模型名、用括号**；`variant` 缺失时连空格与括号一起省略
- 模型名过长时整体截断（`truncateVisual`），保留可辨识前缀：`deepseek-v4.1-fla… (high)`
- **缓存命中率与会话区块同一口径**：`read / (input + write + read)`，一位小数（`model/usage.ts` 的 `cacheRateOf` 是单一事实源，两处共用）。无缓存数据时该行整行不渲染
- 展开状态存**模块级 `Map<sessionID, boolean>`**（内存态，重启即丢，符合「不做持久化」）

### 折叠摘要

标题行：`▼ 子代理 ● 19  ● 0    收起  390.8M`。

- 左端紧跟标题的是**状态指示灯**，右端依次是「收起」操作与合计消耗。
- **「收起」常驻**：有任一条（或折叠行）展开时用正文白（`TEXT_COLOR`），全部收起时用弱化灰（`MUTED_COLOR`，与合计同色）。灰色态点击无效果。
- 点「收起」必须 `stopPropagation()`：标题行整行是区块折叠开关，不拦截会连整个子代理区块一起折叠（上游 `dialog.tsx:458` 同样处理嵌套点击）。

- 状态指示灯的 `badge` 与合计的 `aside` 都吃**全量** `rows`，不受常驻裁剪影响（折叠了也要能看到总数与总量）。
- 合计 = 各子代理 `tokens` 之和。**与我们单项口径一致**（真实累计消耗，含缓存读），因此加总有意义。
- 标题后缀不能拼进 `title`：`Collapsible` 用 `title` 作为折叠状态的 key，拼动态内容会让数量一变就丢失折叠状态。
- **仍然不做**上游那种 `●35 ●1 760.2k $0.03` 徽标：
  - 上游 `●N` 是「已完成数」（含 cancelled），另一个 `●N` 是「失败数」，橙色点才是运行中数——语义不直观
  - 上游的 token 合计是「各子代理最后一次上下文规模横向相加」，不是真实累计消耗，加总无意义（**这一点不适用于我们**，见上）
  - 金额 `$0.03` 明确不做

## 4. 边界与不做的部分

- 无子代理 → 整块不渲染（对齐「无数据区块整块不渲染」）
- 只做**单层折叠**（常驻区 + `还有 N 条已完成`），不做分页 / 虚拟滚动 / 回顶：条目再多也只是多一行折叠行，侧边栏本就由宿主 `scrollbox` 包裹
- 不做「进入会话」跳转：宿主 footer 自带的 `N subagents` 已可跳转
- 不做持久化 / TTL / 多实例合并 / 僵尸清理：实时从 `family()` 读，零状态
- 不做 `task` 工具 part 反查：`family()` 是宿主官方 API，无需解析工具参数
- 入口来源区分（工具调用 vs `spawn` 衍生的后台会话）不展示

## 5. 已知取舍

- 常驻裁剪只省**视觉高度**，不省数据量：`family()` 里的子会话只增不减（宿主行为），19 条时仍要读 19 个 `session.get(id)`（本地内存查询）。真有几百条且实测卡顿，那是渲染量问题，另议。
- 折叠行展开态是组件内存态（`createSignal`），切换会话 / 侧边栏重建后回到默认折叠；与逐条展开态一样不持久化。
- `family()` 依赖宿主已同步子会话列表。若打开一个从未在本进程加载过子会话的旧会话，可能需要一次 `session.sync(sid, {children: true})` 才有数据；宿主进入会话路由时本来就会做这件事，因此正常路径无需我们触发。若实测发现漏，再在 Sidebar 的 memo 里补一次 `void ctx.data.session.sync(sessionID, { children: true })`（幂等、有 `sync.run` 去重）。
